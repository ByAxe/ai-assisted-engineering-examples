# AGENTS.md

## Purpose
audit-log-service: внутренний сервис аудита. Принимает события от других
систем и хранит их неизменяемыми. Главная ценность — доверие: записанное
событие сохраняется как доказательство.

## Project map
- api — граница HTTP: DTO, валидация, контроллеры.
- domain — модель события и доменные инварианты.
- infrastructure — персистентность, маппинг БД, технические интеграции.
- db/migration — миграции Flyway. Структура БД меняется только миграцией.

## Architecture rules
- api может зависеть от domain.
- infrastructure может зависеть от domain.
- domain не зависит ни от api, ни от infrastructure.
- Бизнес-логика живёт в domain, транспорт в api, детали БД в infrastructure.
- Никакой бизнес-логики в контроллерах.

## Hard invariants
- Домен append-only. Событие неизменяемо после записи.
- Никаких операций update/delete над событиями аудита.

## Feedback loop
- Перед отчётом о завершении прогнать минимальную релевантную проверку.
- Доменные/persistence изменения: unit-тесты + интеграционные на Testcontainers,
  проверка применения миграций Flyway.
- Если проверка падает: не объявлять успех, объяснить причину, чинить в рамках задачи.

## Moral invariants
- Не халявить. Например, не пропускать проверки и не подменять их моками ради зелёного пайплайна.
- Не вредить. Например, не делать одни фичи, за счёт вреда другим или более широкому контексту, в котором делаются изменения.
- Быть абсолютно честным: не выдавать незавершённое за готовое.
- Принцип чистоты: не оставлять мусора (того, что не используется или мешает развитию)
